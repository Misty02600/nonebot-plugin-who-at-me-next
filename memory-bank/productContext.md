# 产品上下文

## 问题陈述

旧版 `nonebot-plugin-who-at-me` 可以解决“群消息很多时找不到谁 @ 了我”的问题，但它的实现依赖合并转发节点直接承载原始消息。实际使用中，部分协议端或客户端会丢失、弱化或错误展示 `@` 段和 `reply` 段，用户看到的查询结果可能无法判断到底是谁、在哪条消息里触达了自己。

## 解决方案

新插件会把“记录事实”和“展示方式”分开：

- 记录层保存结构化消息快照，包括原消息段、`@` 目标、回复目标、被引用消息摘要和发送者信息。
- 查询层按用户、群、时间和记录类型筛选。
- 展示层优先生成稳定可读的消息摘要，而不是依赖协议端复原嵌套 `reply` 语义。

## 用户体验

- 用户在群内发送查询命令后，应能快速看到最近谁 `@` 或回复了自己。
- 结果应明确标注记录类型，例如“@ 了你”或“引用/回复了你”。
- 即使客户端不完美支持合并转发，输出也应保留可读文本摘要。
- 清除记录的行为应明确、可预测，不误删其他人的记录。

## 成功标准

- 常见纯文本、图片混合、多个 `@`、`@全体成员`、回复消息都能被稳定记录。
- 查询结果能稳定表达 `@` 目标和回复上下文。
- 存储格式可演进，未来可做迁移而不是只能推倒重来。
- 测试覆盖核心筛选、去重、过期清理、渲染和关键 matcher 行为。
