# 系统模式

## 架构

当前仓库来自 `Misty02600/nonebot-plugin-template`，初始代码仍是模板示例。后续实现建议采用轻量分层：

- `bot` / handlers：注册 NoneBot matcher，负责事件接入、命令入口、API 调用和用户反馈。
- `core`：保存框架无关的领域模型、筛选规则、过期规则、去重规则和输出数据结构。
- `infra`：负责 OneBot v11 消息段转换、持久化、文件/数据库访问、协议端 API 载荷构造。
- application service：仅当查询/清理/记录流程变复杂或复用时再引入，用于编排 core 与 infra。

## 关键模式

### 结构化记录优先

- 目的：避免旧插件把 `Message` 存进 `TextField` 后丢失消息段语义。
- 实现：记录原消息段、被引用消息段、发送者信息、目标用户列表、记录类型和时间戳；渲染时再决定如何输出。

### 快照式稳定展示

- 目的：规避部分协议端对合并转发、伪造节点、嵌套 `reply` 段支持不一致的问题。
- 实现：查询输出明确写出“@ 了你”或“引用/回复了你”，并附带原消息和被引用消息摘要。

### 命令入口收紧

- 目的：旧上游有正则误触发问题，尤其在空命令前缀场景下风险更高。
- 实现：后续命令注册参考 `bot-docs` 的 NoneBot 命令注册实践，优先考虑精确命令或 `on_alconna`，避免宽泛 `on_regex`。

## 组件关系

后续目标流程：

1. message monitor 接收群消息事件。
2. extractor 从 OneBot v11 `Message` / `GroupMessageEvent.reply` 中提取 `@`、回复对象和消息快照。
3. service 判断是否需要记录，并展开或处理 `@all` 策略。
4. repository 保存结构化记录。
5. query command 从 repository 读取记录，按当前群和用户筛选。
6. renderer 生成稳定的用户可读输出。
7. sender 调用 OneBot v11 API 发送普通消息、合并转发或回退输出。
